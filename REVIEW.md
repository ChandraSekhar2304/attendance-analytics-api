List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient` initialization (line 22) | Missing `tz_aware=True` and `serverSelectionTimeoutMS`. PyMongo returns offset-naive datetimes by default, and hangs for 30 seconds if MongoDB is down. | Retrieving records and subtracting against tz-aware IST datetimes raises `TypeError: can't subtract offset-naive and offset-aware datetimes`. Server hangs 30 s on startup when MongoDB is stopped. | Initialized `MongoClient(MONGO_URI, tz_aware=True, serverSelectionTimeoutMS=2000)`. |
| 2 | Startup / Database (lines 22-23) | No database indexes created anywhere in the starter. | All list queries and aggregations across 100k records perform collection scans (`COLLSCAN`), causing `/admin/explain` to fail and requests to time out. | Created unique and compound indexes idempotently during startup (`emp_code` unique, `(emp_code, date)` unique, and compound query indexes) wrapped in try/except. |
| 3 | `compute_late_minutes` (lines 35) | Uses `punch_in.replace()` to set shift start, which adopts the punch's timezone rather than IST, and ignores overnight shifts where punch-in past midnight belongs to the previous day's shift. | Punching in at `00:05` IST on an overnight shift (`22:00-06:00`) anchors shift start at `22:00` of the current day (22 hours in the future), yielding 0 late minutes instead of 125. | Anchored shift start instant on the IST attendance date determined by R1. |
| 4 | `compute_late_minutes` (lines 36-37) | Evaluates `minutes > 10` on floored minutes. At 09:40:01 for a 09:30 shift, elapsed time is 601 s which floors to 10 minutes; `10 > 10` is False, returning 0. | Punch-in at `09:40:01` IST on a `09:30` shift returns `0` instead of `10` (violating R2). | Checked if elapsed seconds strictly exceed 600 seconds (`> 600`), then took `int(seconds // 60)` from shift start. |

| 7 | `compute_overtime` (line 47) | Ignores the minimum 30-minute threshold specified in R3. | Punching out 5 minutes after shift end returns `5` instead of `0`. | Count overtime only if `minutes >= 30`, returning `0` otherwise. |

Also note anything you looked at and decided was **not** a defect, and why:
- **Synchronous `def` handlers with PyMongo**: FastAPI automatically executes synchronous `def` route handlers on an `anyio` worker thread pool, preventing any blocking of the main asyncio event loop. PyMongo provides native connection pooling and thread safety.
- **Dates and times of day stored as plain strings (`YYYY-MM-DD`, `HH:MM`)**: DATA_MODEL.md explicitly mandates plain strings for calendar dates and shift times to prevent timezone coercion.
- **Exclusion of `_id` from API responses**: DATA_MODEL.md explicitly defines `_id` as internal to MongoDB; it must never be exposed or accepted across API payloads.
- **Bare `load_dotenv()`**: In `python-dotenv`, the default behavior is `override=False`, so actual environment variables already take precedence over `.env` without requiring additional flags.
