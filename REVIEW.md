# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `load_dotenv()` (line 20) | Environment variable precedence. Calling `load_dotenv()` without `override=False` can override actual system/container environment variables. | Running with `MONGO_URI="mongodb://production:27017"` in env while a local `.env` has localhost connects to localhost. | Changed to `load_dotenv(override=False)` ensuring environment variables always win. |
| 2 | `MongoClient(...)` (line 22) | Missing `tz_aware=True` and connection timeout. By default PyMongo returns naive datetimes in UTC, causing `TypeError` when combined with timezone-aware IST datetimes. Also lacks `serverSelectionTimeoutMS`. | Combining retrieved `punch_in` with IST datetime raises `TypeError: can't subtract offset-naive and offset-aware datetimes`. Hangs for 30s if Mongo is down. | Initialized `MongoClient(MONGO_URI, tz_aware=True, serverSelectionTimeoutMS=2000)`. |
| 3 | Startup / Index creation | Missing index initialization. Collections have no indexes except `_id`. List and analytics queries perform collection scans (COLLSCAN) across 100k records. | Queries on 100k documents take seconds; `/admin/explain` fails checking for `IXSCAN` and lack of `COLLSCAN`. | Created required unique and compound indexes idempotently at startup using `create_index()`, resilient to Mongo downtime. |
| 4 | `compute_late_minutes` (lines 33-37) | Grace period logic evaluates `minutes if minutes > 10 else 0`. Because `minutes = int(seconds / 60)`, a punch at 09:40:01 yields 10 minutes (`10 > 10` is False), incorrectly returning 0. | Punch-in at `09:40:01` IST on a `09:30` shift returns `0` instead of `10` (violating R2). | Checked if total elapsed seconds strictly exceed 600 seconds (`> 10 * 60`), then took `floor(seconds / 60)` from shift start. |
| 5 | `compute_late_minutes` (lines 33-37) | Overnight shifts break. For overnight shifts (e.g. 22:00 to 06:00), a punch-in past midnight (e.g. 00:05) uses `punch_in.replace(hour=22)` on the current day, creating a shift start 22 hours in the future. | Punch-in at `00:05` IST for a `22:00-06:00` shift computes negative difference and returns 0 instead of 125 late minutes. | Anchored shift start instant on the actual attendance date (which R1 places on the previous calendar day). |
| 6 | Helpers (lines 33-47) | Missing instant truncation to whole seconds before calculations. | Punch-in at `09:40:00.900` counts as 600.9s elapsed rather than exactly 600s (09:40:00), erroneously triggering late minutes. | Truncate all epoch milliseconds to whole seconds `(ms // 1000) * 1000` at the API boundary before calculation and storage. |
| 7 | `compute_work_hours` (lines 40-41) | Python's `round()` uses Banker's Rounding (round half to even) rather than exact half-up rounding (R4). | Duration of 2.125 hours rounds to `2.12` instead of `2.13`. | Implemented exact half-up rounding via `Decimal(str(val)).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. |
| 8 | `compute_overtime` (lines 44-47) | Minimum 30-minute overtime threshold ignored. Code does `max(0, minutes)` without enforcing the `>= 30` requirement of R3. | Punch-out 5 minutes after shift end returns `5` instead of `0`. | Count overtime only if `diff_minutes >= 30`, otherwise return `0`. |
| 9 | `compute_overtime` (lines 44-47) | Overnight shifts end on the next calendar day. Code anchors `end` on `date_str` (attendance date), creating shift end on the previous day. | Overnight shift ending at `06:00` with punch-out at `06:40` on day 2 compares with day 1 `06:00`, returning >1400 overtime minutes. | Added check: if `shift_end <= shift_start`, set `shift_end_date = attendance_date + timedelta(days=1)`. |
| 10 | `GET /health` (lines 72-74) | Unconditional 200 OK without verifying database readiness. | Shutting down MongoDB still yields `200 {"status": "ok"}` from `/health` instead of `503`. | Pinged database with `client.admin.command('ping')`; return 503 if unreachable. |
| 11 | `POST /employees` (lines 79-85) | Check-then-insert race condition for `emp_code`. | Concurrent requests with the same `emp_code` both pass `find_one` and create duplicates or throw unhandled 500s. | Enforced database unique index on `emp_code`, used bare `insert_one`, and caught `DuplicateKeyError -> 409`. |
| 12 | `EmployeeIn` / `POST /employees` (lines 53-61, 82) | Missing schema validations: `emp_code` regex (`^EMP\d{4,6}$`), `shift_start != shift_end` (equal shifts must 422), valid calendar date `joined_on`. `created_at` set to naive `now()` and leaked as non-epoch ms. | Input `shift_start="09:00", shift_end="09:00"` accepted with 201; `created_at` returned as ISO string instead of epoch ms integer. | Added Pydantic field validators and model validators; formatted `created_at` as UTC BSON in DB and epoch ms in response. |
| 13 | `GET /employees` (lines 89-96) | Off-by-one pagination (`skip = page * page_size`), total ignores filter, missing sort. | Requesting `page=1` skips the first 20 employees; `total` counts whole collection even when filtered by `department`. | Set `skip = (page - 1) * page_size`, `total = count_documents(q)`, sort by `emp_code` asc, validated pagination query bounds. |
| 14 | `POST /attendance/punch-in` (lines 101-113) | Missing 404 check for unknown employee. | `POST /attendance/punch-in` with non-existent `emp_code` raises `TypeError: 'NoneType' object is not subscriptable` -> 500. | Check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 15 | `POST /attendance/punch-in` (lines 102-103) | Attendance date calculation uses naive local date instead of IST calendar date, and ignores overnight shifts (R1). | Overnight punch-in at `05:30` IST for a `22:00-06:00` shift assigned to today rather than the previous calendar day. | Converted punch instant to IST and applied R1 overnight rules (if time < shift_end, assign previous day). |
| 16 | `POST /attendance/punch-in` (lines 104-105) | Check-then-insert race condition on `(emp_code, date)` and status validation missing. | Concurrent punch-ins both pass `find_one`; accepting `ABSENT` or `LEAVE` at punch-in succeeds with 201 instead of 422. | Validated status in `[PRESENT, WFH, ON_DUTY]` (else 422); created unique index on `(emp_code, date)` and handled `DuplicateKeyError -> 409`. |
| 17 | `POST /attendance/punch-in` (lines 119-120) | Response schema leaks MongoDB `id` / `_id` and raw datetime types. | Response payload has `id: str` (not present in OpenAPI `AttendanceRecord`) and raw datetime for `punch_in`. | Formatted response per `AttendanceRecord` schema with epoch ms integers and no `id` or `_id`. |
| 18 | `GET /attendance` (lines 144-147) | Entire collection loaded into memory: `docs = list(db.attendance_logs.find(q))` and sorted in Python. | On a dataset of ~100,000 records, exhausts server memory and causes severe latency / timeout. | Replaced with indexed MongoDB cursor `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` and `count_documents(q)`. |
| 19 | `GET /attendance` (line 145) | Incomplete and unstable sort order. Starter sorts only by `date` desc. | Multiple records on the same date return in arbitrary / non-deterministic order. | Applied compound sort by `date` descending, then `emp_code` ascending. |
| 20 | `GET /attendance` (lines 136-141) | Missing validation for `date_from > date_to`. | Query `date_from=2026-07-10&date_to=2026-07-05` returns empty list 200 OK instead of HTTP 422. | Added validation `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |
| 21 | Instants validation throughout | Accepts strings, floats, booleans, and seconds-looking timestamps without 422 validation. | `punched_at="1783312500000"` or `punched_at=1783312500` (seconds) accepted. | Added pre-validation checking `isinstance(v, int) and not isinstance(v, bool)` and `100000000000 <= v <= 4102444800000`, else 422. |

Also note anything you looked at and decided was **not** a defect, and why:
- **Synchronous `def` route handlers with PyMongo**: Examined whether using synchronous PyMongo functions inside FastAPI route handlers was a defect compared to Motor/asyncio. In FastAPI, standard `def` endpoints are automatically offloaded to an `anyio` worker thread pool, preventing any blocking of the main asyncio event loop. Given PyMongo's battle-tested connection pooling and the assignment guidelines, sync PyMongo handlers are thread-safe, fast, and appropriate.
- **Storing dates and times as strings (`YYYY-MM-DD`, `HH:MM`)**: Examined whether dates and shift times should be stored as BSON datetimes. DATA_MODEL.md section 1 explicitly states that calendar dates and shift times of day are plain strings on purpose to prevent timezone coercion.
- **Exclusion of `_id` from API responses**: Examined whether `_id` should be included or converted. DATA_MODEL.md explicitly defines `_id` as internal to MongoDB, never to be accepted or returned by the API.
